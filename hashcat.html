Web Browser

On the transport level, the browser connects to:
TCP port 80 by default when the website is accessed over HTTP
TCP port 443 by default when the website is accessed over HTTPS
For instance, https://127.0.0.1:8834/ will connect to 127.0.0.1 (localhost) at port 8834 via HTTPS protocol. If there is an HTTPS server listening on that port, we will receive a web page.
While browsing a web page, you can press Ctrl+Shift+I on a PC to open the Developer Tools on Firefox
For instance, you can view and even modify the JavaScript (JS) files, inspect the cookies set on your system and discover the folder structure of the site content.

There are also plenty of add-ons for Firefox and Chrome that can help in penetration testing. Here are a few examples:

FoxyProxy lets you quickly change the proxy server you are using to access the target website. This browser extension is convenient when you are using a tool such as Burp Suite or if you need to switch proxy servers regularly. You can get FoxyProxy for Firefox from here > FoxyProxy
User-Agent Switcher and Manager gives you the ability to pretend to be accessing the webpage from a different operating system or different web browser. In other words, you can pretend to be browsing a site using an iPhone when in fact, you are accessing it from Mozilla Firefox. You can download User-Agent Switcher and Manager for Firefox here > User-Agent
Wappalyzer provides insights about the technologies used on the visited websites. Such extension is handy, primarily when you collect all this information while browsing the website like any other user. A screenshot of Wappalyzer is shown below. You can find Wappalyzer for Firefox here > Wappalyzer

Ping

The primary purpose of ping is to check whether you can reach the remote system and that the remote system can reach you back.
the ping is a command that sends an ICMP Echo packet to a remote system. If the remote system is online, and the ping packet was correctly routed and not blocked by any firewall, the remote system should send back an ICMP Echo Reply.
ping HOSTNAME

If you don’t specify the count on a Linux system, you will need to hit CTRL+c to force it to stop. Hence, you might consider ping -c 10 10.114.137.163 if you just want to send ten packets. This is equivalent to ping -n 10 10.114.137.163 on a MS Windows system.

"From a penetration testing point of view, we will try to discover more about this target. We will try to learn as much as possible, for example, which ports are open and which services are running."
Generally speaking, when we don’t get a ping reply back, there are a few explanations that would explain why we didn’t get a ping reply, for example:
The destination computer is not responsive; possibly still booting up or turned off, or the OS has crashed.
It is unplugged from the network, or there is a faulty network device across the path.
A firewall is configured to block such packets. The firewall might be a piece of software running on the system itself or a separate network appliance. Note that MS Windows firewall blocks ping by default.
Your system is unplugged from the network.

Use the "man ping" command on a Linux system to consult ping's manual pages. Alternatively, check the following extract from the manual page:ping [-c count] [-i interval] [-I interface] [-W timeout] [-p pattern] [-s packetsize] [-t ttl] [-T timestamp option] [hop...] {destination}

Traceroute

The traceroute command traces the route taken by the packets from your system to another host. The purpose of a traceroute is to find the IP addresses of the routers or hops that a packet traverses as it goes from your system to a target host.
On Linux and macOS, the command to use is traceroute 10.114.137.163, and on MS Windows, it is tracert 10.114.137.163. traceroute tries to discover the routers across the path from your system to the target system.

Su Linux, traceroute inizierà inviando datagrammi UDP all'interno di pacchetti IP di TTL essere 1. Pertanto, fa sì che il primo router incontri un TTL=0 e inviare un ICMP Time-to-Live superato indietro. Quindi, a TTL di 1 vi rivelerà l'indirizzo IP del primo router. Quindi invierà un altro pacchetto con TTL=2; questo pacchetto verrà eliminato al secondo router. E così via.
da tracert notiamo:
- abbiamo linee numerate; ogni linea rappresenta un router/hop.
- Il nostro sistema invia tre pacchetti con TTL impostato su 1, poi tre pacchetti con TTL impostato su 2 e così via.
- A seconda della topologia di rete, potremmo ottenere risposte da un massimo di 3 router diversi, a seconda del percorso seguito dal pacchetto.
- La linea 12 99.83.69.207 (99.83.69.207) 17.603 ms 15.827 ms 17.351 ms ha abbandonato il pacchetto tre volte e ha inviato un messaggio di transito con tempo ICMP superato.
- La linea 3 * 100.66.16.176 (100.66.16.176) 8.006 ms * indica che il nostro sistema non ha ricevuto due messaggi in transito con tempo ICMP previsto superato.
- La linea 1 ec2-3-248-240-5.eu-west-1.compute.amazonaws.com (3.248.240.5) 2.663 ms * ec2-3-248-240-13.eu-west-1.compute.amazonaws.com (3.248.240.13) 7.468 ms possiamo vedere che i pacchetti che escono dall'AttackBox prendono percorsi diversi. Possiamo vedere due router che hanno risposto al fatto che TTL fosse uno solo. Il nostro sistema non ha mai ricevuto il terzo messaggio ICMP previsto.

Non possiamo aspettarci che il percorso rimanga fisso quando i pacchetti devono passare tramite altri router al di fuori della nostra rete.
Per riassumere, possiamo notare quanto segue
-Il numero di salti/router tra il sistema e il sistema di destinazione dipende dal tempo in cui si esegue traceroute. Non vi è alcuna garanzia che i vostri pacchetti seguiranno sempre lo stesso percorso, anche se siete sulla stessa rete o ripetete il comando traceroute in breve tempo.
-Alcuni router restituiscono un indirizzo IP pubblico. Potresti esaminare alcuni di questi router in base all'ambito del test di penetrazione previsto.
-Alcuni router non restituiscono una risposta.

Telnet

Il protocollo TELNET (Teletype Network) è stato sviluppato nel 1969 per comunicare con un sistema remoto tramite un'interfaccia a riga di comando (command-line interface)CLI). Quindi, il comando telnet utilizza il protocollo TELNET per l'amministrazione remota. La porta predefinita utilizzata da telnet è 23. Dal punto di vista della sicurezza, telnet invia tutti i dati, inclusi nomi utente e password, in chiaro. L'invio in testo non crittografato rende facile per chiunque abbia accesso al canale di comunicazione rubare le credenziali di accesso. L'alternativa sicura è il protocollo SSH (Secure SHell).
-> Sapendo che il client telnet si basa sul protocollo TCP, è possibile utilizzare Telnet per connettersi a qualsiasi servizio e afferrare il suo header. Utilizzando telnet MACHINE_IP PORTA è possibile connettersi a qualsiasi servizio in esecuzione TCP e scambia anche qualche messaggio a meno che non utilizzi la crittografia.
-> Se volessimo scoprire maggiori informazioni su un server web, in ascolto sulla porta 80:
1) connessione al server alla porta 80 e poi comunichiamo usando il protocollo HTTP;
2) Per specificare qualcosa di diverso dalla pagina indice predefinita, è possibile emettere GET /page.html HTTP/1.1, che richiederà pagina.html;
3) Per ottenere una risposta valida, invece di un errore, è necessario inserire un valore per l'host host: esempio e premi invio due volte.
-> Di particolare interesse per noi è scoprire il tipo e la versione del server web installato, Server: nginx/1.6.2. ; Se ci connettiamo a un server di posta, dobbiamo utilizzare comandi adeguati basati sul protocollo, come ad esempio SMTP e POP3.
ESEMPIO:
1) telnet 10.114.140.157 80
2)GET /HTTP/1.1 host:esempio
3) si puo estrapolare nome e versione server

Netcat

Netcat o semplicemente nc ha diverse applicazioni che possono essere di grande valore per un pentester. Netcat supporta ia i protocolli TCP che UDP. Può funzionare come un client che si connette a una porta di ascolto; in alternativa, può agire come un server che ascolta su una porta di tua scelta.
1) per raccogliere il suo header utilizza: nc MACCHINA_IP 80
NB) Tieni presente che potrebbe essere necessario premere MAIUSC+INVIO dopo la riga GET
2)GET /HTTP/1.1 (stiamo specificando al server di destinazione che il nostro client supporta HTTP versione 1.1. ) ;
3) Infine, dobbiamo dare un nome al nostro host, quindi abbiamo aggiunto su una nuova linea: host: netcat ;

Su Server-Side è possibile utilizzare netcat per ascoltare su una porta TCP e connettersi a una porta di ascolto su un altro sistema:
-E' possibile emettere nc-lp 1234 o meglio ancora, nc-vnlp 1234, che equivale a nc -v -l -n -p 1234
-L'ordine esatto delle lettere non ha importanza finché il numero della porta è preceduto direttamente da -P.
opzione + significato
-l = Modalità ascolto
-P = Specificare il numero della Porta
-N = Solo numerico; nessuna risoluzione dei nomi host tramite DNS
-v = Uscita Verbose (opzionale, ma utile per scoprire eventuali bug)
-vv = Verbosissimo (opzionale)
-K = Continua ad ascoltare dopo che il client si è disconnesso
Note:
l'opzione -P dovrebbe apparire appena prima del numero di porta su cui si desidera ascoltare.
l'opzione -N eviterà ricerche e avvisi DNS.
i numeri di porta inferiori a 1024 richiedono privilegi di root per essere ascoltati.

Su Client-Side pubblicheresti nc 10.114.157.210 PORTA_NUMERO ;
Sul lato server ascolteremo sulla porta 1234. Possiamo raggiungere questo obiettivo con il comando nc-vnlp 1234 (uguale a nc-lvnp 1234). Nel nostro caso, il server di ascolto ha l'indirizzo IP 10.114.157.210, quindi possiamo connetterci ad esso dal lato client eseguendo nc 10.114.157.210 1234. Questa configurazione riecheggerebbe qualunque cosa digiti da un lato all'altro lato del TCP tunnel.
