Nmap Live Host Discovery

Quali sistemi sono attivi? Quali servizi sono in esecuzione in questi sistemi?
Scoprire i sistemi online prima della scansione delle porte: Questa fase è cruciale perché tentare di eseguire la scansione dei sistemi offline farà perdere tempo e genera rumore di rete!
Diversi approcci che Nmap usi per scoprire host dal vivo:
1) ARP scan : Questa scansione utilizza ARP richieste per scoprire live hosts;
-ARP scan is possible only if you are on the same subnet as the target systems. On an Ethernet (802.3) and WiFi (802.11), you need to know the MAC address of any system before you can communicate with it
If you want Nmap only to perform an ARP scan without port-scanning, you can use nmap -PR -sn TARGETS, where -PR indicates that you only want an ARP scan

2) ICMP scan: Questa scansione utilizza le richieste ICMP per identificare i live hosts
-We can ping every IP address on a target network and see who would respond to our ping (ICMP Type 8/Echo) requests with a ping reply (ICMP Type 0).
-Many firewalls block ICMP echo; new versions of MS Windows are configured with a host firewall that blocks ICMP echo requests by default. Remember that an ARP query precedes an ICMP request if your target is on the same subnet.
-To use ICMP echo request to discover live hosts, add the option -PE. (Remember to add -sn if you don’t want to follow that with a port scan.)
-Because ICMP echo requests tend to be blocked, you might also consider ICMP Timestamp or ICMP Address Mask requests to tell if a system is online. Nmap uses a timestamp request (ICMP Type 13) and checks whether it will get a Timestamp reply (ICMP Type 14). Adding the -PP option tells Nmap to use ICMP timestamp requests.
-Similarly, Nmap uses address mask queries (ICMP Type 17) and checks whether it gets an address mask reply (ICMP Type 18). This scan can be enabled with the option -PM.
-It is essential to learn multiple approaches to achieve the same result. If one packet type is blocked, we can always choose another to discover the target network and services.

3) TCP/UDP ping: Questa scansione invia i pacchetti a TCP porti e UDP porte per determinare i live hosts

1) When a privileged user tries to scan targets on a local network (Ethernet), Nmap uses ARP requests. A privileged user is root or a user who belongs to sudoers and can run sudo.
2) When a privileged user tries to scan targets outside the local network, Nmap uses ICMP echo requests, TCP ACK (Acknowledge) to port 80, TCP SYN (Synchronize) to port 443, and ICMP timestamp request.
3) When an unprivileged user tries to scan targets outside the local network, Nmap resorts to a TCP 3-way handshake by sending SYN packets to ports 80 and 443.

Scan Type + Example Command
ARP Scan > sudo nmap -PR -sn MACHINE_IP/24
ICMP Echo Scan > sudo nmap -PE -sn MACHINE_IP/24
ICMP Timestamp Scan > sudo nmap -PP -sn MACHINE_IP/24
ICMP Address Mask Scan > sudo nmap -PM -sn MACHINE_IP/24
TCP SYN Ping Scan > sudo nmap -PS22,80,443 -sn MACHINE_IP/30
TCP ACK Ping Scan > sudo nmap -PA22,80,443 -sn MACHINE_IP/30
UDP Ping Scan > sudo nmap -PU53,161,162 -sn MACHINE_IP/30

Remember to add -sn if you are only interested in host discovery without port-scanning. Omitting -sn will let Nmap default to scanning live hosts for ports.

Option + Purpose
-n > no DNS lookup
-R > reverse-DNS lookup for all hosts
-sn > host discovery only

Nmap Basic Port Scans

TCP SYN Scan: requires a privileged (root or sudoer) user to run it; does not need to complete the TCP 3-way handshake;Because we didn’t establish a TCP connection, this decreases the chances of the scan being logged.

UDP Scan: it does not require any handshake for connection establishment;We cannot guarantee that a service listening on a UDP port would respond to our packets; if a UDP packet is sent to a closed port, an ICMP port unreachable error (type 3, code 3) is returned.

Port Scan Type + Example Command
TCP Connect Scan > nmap -sT MACHINE_IP
TCP SYN Scan > sudo nmap -sS MACHINE_IP
UDP Scan > sudo nmap -sU MACHINE_IP

These scan types should get you started discovering running TCP and UDP services on a target host.

Option Purpose
-p- > all ports
-p1-1023 > scan ports 1 to 1023
-F > 100 most common ports
-r > scan ports in consecutive order
-T<0-5> > -T0 being the slowest and T5 the fastest
--max-rate 50 rate > <= 50 packets/sec
--min-rate 15 rate > >= 15 packets/sec
--min-parallelism 100 > at least 100 probes in parallel

Nmap Advanced Port Scans

TCP Null Scan, FIN Scan, and Xmas Scan: Null , Fin e Xmas Scan ricevono una risposta solo nel caso la porta sia chiusa, quindi le restanti porte possono essere aperte o bloccate da regole Firewall. Queste scansioni utili solo nel caso di un Firewall stateless, in quanto controlla solo i pacchetti con SYN flag che tentano la connessione.

TCP Maimon Scan:Inutile nella maggiorparte dei casi nelle reti moderne. Non vale la pena inserirla nel mio cheatsheet per CTF.

TCP ACK, Window, and Custom Scan: TCP ACK scan sarebbe utile nel caso il firewall sta davanti al nostro target; in questo caso in base a quali pacchetti ACK hanno prodotto risposte, saremo in grado di conoscere quali porte non son state bloccate dal firewall; questo tipo di scansione è adatto per scoprire " set di regole e configurazione del firewall".
Questo scan può essere eseguito dopo TCP Syn scan o TCP Null/Fin/Xmas scan, nel caso non ho ricevuto risposte chiare ( tipo filtrato). Window Scan è un alternativa a TCP ACK.
In conclusione questi due scan son molto efficienti per mappare le regole del Firewall; da RICORDARE che se un firewall non blocca una porta specifica, non significa che un servizio sia in ascolto su quella porta. Esiste la possibilità che le regole del firewall devono essere aggiornate per le recenti modifiche al servizio.

Spoofing and Decoys: -In alcune configurazioni di rete, sarai in grado di scansionare un sistema di destinazione utilizzando un indirizzo IP falsificato e persino un MAC address falsificato.
-Tale scansione è utile solo in una situazione in cui puoi garantire di catturare la risposta.
-Se provi a scansionare un target da una rete casuale utilizzando un indirizzo IP falsificato, è probabile che non avrai alcuna risposta instradata e i risultati della scansione potrebbero essere inaffidabili

Fragmented Packets: dipende dal tipo di firewall/IDS, può risultare utile dividere i pacchetti in dimensioni più ridotte.

Idle/Zombie Scan: Lo spoofing dell'indirizzo IP di origine può essere un ottimo approccio alla scansione furtiva. Tuttavia, lo spoofing funzionerà solo in configurazioni di rete specifiche. Richiede di essere in una posizione in cui è possibile monitorare il traffico. Considerando questi limitazioni, lo spoofing del tuo indirizzo IP può avere poca utilità; tuttavia, possiamo fornirgli un upgrade con la scansione idle.
Leggere Approfondimenti su Nmap Extra per saperne di più

Port Scan Type + Example Command
TCP Null Scan > sudo nmap -sN 10.114.186.237 TCP FIN Scan > sudo nmap -sF 10.114.186.237 TCP Xmas Scan > sudo nmap -sX 10.114.186.237 TCP Maimon Scan > sudo nmap -sM 10.114.186.237 TCP ACK Scan > sudo nmap -sA 10.114.186.237 TCP Window Scan > sudo nmap -sW 10.114.186.237 Custom TCP Scan > sudo nmap --scanflags URGACKPSHRSTSYNFIN 10.114.186.237 Spoofed Source IP > sudo nmap -S SPOOFED_IP 10.114.186.237 Spoofed MAC Address > --spoof-mac SPOOFED_MAC Decoy Scan > nmap -D DECOY_IP,ME 10.114.186.237 Idle (Zombie) Scan > sudo nmap -sI ZOMBIE_IP 10.114.186.237 Fragment IP data into 8 bytes > -f Fragment IP data into 16 bytes > -ff Option + Purpose
--source-port PORT_NUM > specify source port number
--data-length NUM > append random data to reach given length

These scan types rely on setting TCP flags in unexpected ways to prompt ports for a reply. Null, FIN, and Xmas scan provoke a response from closed ports, while Maimon, ACK, and Window scans provoke a response from open and closed ports.
Option + Purpose
--reason > explains how Nmap made its conclusion
-v > verbose
-vv > very verbose
-d > debugging
-dd > more details for debugging

Nmap Post Port Scans

Option + Meaning
-sV > determine service/version info on open ports (stabilisce una connessione TCP 3-way)
-sV --version-light > try the most likely probes (2)
-sV --version-all > try all available probes (9)
-O > detect OS
--traceroute > run traceroute to target
--script=SCRIPTS > Nmap scripts to run (per + info, leggi Nmap Extra)
-sC or --script=default > run default scripts
-A > equivalent to -sV -O -sC --traceroute
-oN > save output in normal format
-oG > save output in grepable format
-oX > save output in XML format
-oA > save output in normal, XML and Grepable formats
