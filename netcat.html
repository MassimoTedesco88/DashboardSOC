[NETCAT]

Netcat is the most basic tool in a pentester's toolkit when it comes to any kind of networking.

Reverse Shells

The syntax for starting a netcat listener using Linux is this:
nc -lvnp port-number
-l is used to tell netcat that this will be a listener
-v is used to request a verbose output
-n tells netcat not to resolve host names or use DNS. Explaining this is outwith the scope of the room.
-p indicates that the port specification will follow.
Realisticamente potresti utilizzare qualsiasi porta che ti piace, purché non ci sia già un servizio che la utilizza. Tieni presente che se scegli di utilizzare una porta inferiore a 1024, dovrai utilizzarla sudo all'avvio del tuo ascoltatore. Detto questo, è spesso una buona idea utilizzare un numero di porta ben noto (80, 443 o 53 sono buone scelte) poiché è più probabile che questo superi le regole del firewall in uscita sul bersaglio.
sudo nc -lvnp 443

Bind Shells

Se stiamo cercando di ottenere una bindshell su un bersaglio allora possiamo supporre che ci sia già un ascoltatore che ci aspetta su una porta scelta del bersaglio: tutto quello che dobbiamo fare è connetterci ad esso. La sintassi per questo è relativamente semplice:
nc target-ip chosen-port
Qui stiamo utilizzando netcat per effettuare una connessione in uscita al target sulla porta scelta.

Netcat Shell Stabilisation

1.Step completato = abbiamo catturato o collegato a una shell netcat
2. Step = there are many ways to stabilise netcat shells on Linux systems. We'll be looking at three here.

Technique 1: Python

The first technique we'll be discussing is applicable only to Linux boxes, as they will nearly always have Python installed by default. This is a three stage process:
1) The first thing to do is use python -c 'import pty;pty.spawn("/bin/bash")', which uses Python to spawn a better featured bash shell; note that some targets may need the version of Python specified. If this is the case, replace python with python2 or python3 as required. At this point our shell will look a bit prettier, but we still won't be able to use tab autocomplete or the arrow keys, and Ctrl + C will still kill the shell.
2) Step two is: export TERM=xterm -- this will give us access to term commands such as clear.
3) Finally (and most importantly) we will background the shell using Ctrl + Z. Back in our own terminal we use stty raw -echo; fg. This does two things: first, it turns off our own terminal echo (which gives us access to tab autocompletes, the arrow keys, and Ctrl + C to kill processes). It then foregrounds the shell, thus completing the process.
Note that if the shell dies, any input in your own terminal will not be visible (as a result of having disabled terminal echo). To fix this, type reset and press enter.

Technique 2: rlwrap

rlwrap is a program which, in simple terms, gives us access to history, tab autocompletion and the arrow keys immediately upon receiving a shell; however, some manual stabilisation must still be utilised if you want to be able to use Ctrl + C inside the shell. rlwrap is not installed by default on Kali, so first install it with sudo apt install rlwrap.
To use rlwrap, we invoke a slightly different listener:rlwrap nc -lvnp port
Prepending our netcat listener with "rlwrap" gives us a much more fully featured shell. This technique is particularly useful when dealing with Windows shells, which are otherwise notoriously difficult to stabilise. When dealing with a Linux target, it's possible to completely stabilise, by using the same trick as in step three of the previous technique: background the shell with Ctrl + Z, then use stty raw -echo; fg to stabilise and re-enter the shell.
